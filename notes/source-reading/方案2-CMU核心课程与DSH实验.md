## 课程依据

本次讨论核对了 CMU 11-768 AI Agents 的 2026 年秋季课程页面和作业1说明。课程仍在进行，后续材料及要求以官方发布为准。

课程前七讲覆盖 Agent 基础、工具使用、上下文管理、Skills 与记忆、规划与多 Agent、Coding Agent、GUI Agent。

作业1要求实现 Agent 循环，让 Coding Agent 修复棋类应用，研究上下文压缩，再让另一 Agent 操作修好的应用；其中包含上下文和观察信息的对照实验。后续作业主题分别是评估与训练。这些是本方案借鉴的教学结构，不代表已经完成原课程作业。

## 核心模块与 DSH 实验

| 课程主题 | DSH 实验 | 要回答的问题 |
| --- | --- | --- |
| Agent 循环与工具 | 跟踪一次读代码、修改、执行、继续的过程，再故意制造工具失败 | 模型依据什么决定下一步？失败怎样反馈给它？ |
| 上下文管理 | 在同一个较长任务上比较不同压缩设置，检查实际输入与结果 | 哪些信息丢失会导致失败？节省上下文有什么代价？ |
| Skills 与记忆 | 把浏览器验收流程做成 Skill，比较启用前后 | 是否更稳定地执行验收？实际改善来自哪里？ |
| 规划与多 Agent | 比较单 Agent 与开发者、浏览器测试者分工 | 分工是否提高成功率？额外耗时与调用量是否值得？ |
| Coding / GUI Agent | 实现方案1中的浏览器复现、修复和再次验收 | 代码测试通过与实际页面可用有哪些差别？ |
| 评估 | 保留固定任务，每次改动后复测，并留少量新任务检查迁移 | 改善能否迁移到相近任务？是否只适配了某个案例？ |

实验继续使用同一个 Agent 和任务环境，围绕实际行为展开源码阅读。涉及浏览器结构操作与视觉 Computer Use 的区别、接入基础和待验证项，见方案1。

## 保留一次极简 Agent 循环实现

在学习仓库的独立实验中，自己实现一次极简 Agent 循环，包含：

1. 构造消息。
2. 调用模型。
3. 解析并执行工具调用。
4. 回填与调用对应的结果。
5. 判断结束。
6. 处理工具失败和步数上限。

随后在 DSH 中找到这些职责对应的实现，并用运行记录解释一次真实执行。教学实验保持小范围；实际 Agent 产品沿用 DSH 的具名 profile 启动方式和文档化扩展点。

每轮记录中都要写清楚：哪些能力由 DSH 提供，哪些是这次自己实现或改变的。仅启用已有循环、压缩或 Skills，不能视作完成了原课程对应的实现学习目标。

## 执行顺序

1. 先用方案1跑通一次浏览器复现、代码修复和验收，获得可实际使用的 Agent，并保留初始运行记录。
2. 完成一次极简循环实验，再对应到 DSH 的工具执行和会话流程。
3. 按核心模块持续改造同一个 Agent，每轮围绕一个明确问题展开。
4. 在改造早期建立固定任务与验收条件，持续复测，并用保留的新任务检查迁移。
5. 根据实际问题选择后续课程内容。

学习进度按实验结果推进。可复现实验放入 `labs/<三位编号-主题>/`，记录目的、环境、步骤、结果和结论。

## 每轮产出与掌握标准

每轮留下四样东西：

- **一个预测：** 预计改动会影响什么行为，为什么。
- **一处实现：** 明确自己修改的配置、工具或事件扩展点。
- **一组对照结果：** 在尽量相同的任务和运行条件下，比较修改前后的行为、成功情况、耗时或调用量，并保留失败记录。
- **一段自己的解释：** 说明预测与观察是否一致，还有什么不能确定。

生成结果存在随机性，少量学习实验只能说明本次观察，不能直接当作统计可靠的性能结论。

能够预测改动的影响、找到对应源码、解释实验结果，并独立处理一个相近需求，才说明这一轮形成了可迁移的理解。
